# مشخصات صفحه‌های اپ پیک
(ورود = از کجا؛ خروج = به کجا. برگشت همیشه به صفحه‌ی قبلی دقیق.)

| صفحه | ورود | محتوا/وضعیت‌ها | اکشن‌ها / API |
|---|---|---|---|
| ورود | شروع | شماره، OTP؛ کارت کوکی بار اول | `POST /c/auth/otp`, `/c/auth/verify` → اگر تأییدنشده: انتظار، وگرنه سفارش‌ها |
| ثبت‌نام | ورود | ۴ مرحله: اطلاعات (نام، کدملی، پلاک)، مدارک (data-driven)، شبا، ثبت | `GET /c/doc-types`, `POST /c/registration`, آپلود مدرک |
| انتظار تأیید | ورود/ثبت‌نام | پیام و خروج | `GET /c/me` (status) |
| مجوزهای دستگاه | تأیید مدیر / حساب | موقعیت همیشه، اعلان، باتری؛ ادامه فقط با موقعیت+اعلان | Capacitor permissions |
| سفارش‌ها (تب) | بعد از مجوز | CHeader، کلید آنلاین، پیشنهادها، بنر سفارش در جریان، خالی/آفلاین | `PUT /c/status`, WS `offers`, `GET /c/offers` |
| هشدار سفارش | تپ کارت یا WS | تایمر ۳۰ثانیه، درآمد، مبدأ/مقصد (محله)، نقد/آنلاین | `POST /c/offers/{id}/accept` (۴۰۹ = برداشته شد), `/reject` |
| سفارش (مراحل) | قبول سفارش/بنر | رستوران (نقشه، تماس) → تحویل‌گیری (تیک غذاها، گزارش مشکل) → مشتری (نقشه، تماس، «در دسترس نیست») → تحویل (نقد/آنلاین) → خلاصه | `POST /c/orders/{id}/stage`, `/withdraw`, `/issue`, `/unreachable`, `/deliver` |
| انصراف | مرحله‌ی رستوران/تحویل‌گیری | ReasonSheet با دلیل | فقط قبل از تحویل‌گیری |
| درآمد (تب) | تب | بازه (امروز/هفته/ماه)، مانده، آمار، نمودار | `GET /c/earnings?period=` |
| تاریخچه + جزئیات | درآمد/حساب | فهرست و جزئیات | `GET /c/orders/history` |
| تسویه‌ها | درآمد/حساب | واریزهای هفتگی | `GET /c/settlements` |
| حساب (تب) | تب | کارت پیک، اطلاعات، مدارک (نقطه‌ی هشدار)، تاریخچه، تسویه، مجوزها، کوکی، پشتیبانی، تیره، خروج | |
| اطلاعات من | حساب | نام، موبایل، کدملی و شبا ماسک | تغییر شبا = OTP تازه + بررسی مدیر `POST /c/sheba-change` |
| مدارک من | حساب | وضعیت ok/wait/bad، تمدید | `POST /c/documents/{type}` |
| پشتیبانی | حساب/جزئیات | تماس فوری مدیر شهر، پشتیبانی، FAQ | |
| کوکی‌ها | ورود/حساب | ضروری (ثابت)، عملکرد، آمار | ذخیره‌ی سمت کلاینت + `PUT /c/consent` |
| آفلاین | سراسری | ErrorPage | تلاش دوباره |

## قوانین تکمیلی
- انصراف/آفلاین‌شدن: تا پایان سفارش آفلاین ممنوع.
- «مشتری در دسترس نیست»: دیالوگ تأیید + گزارش به مدیر شهر (صفحه‌ی جدا ندارد)؛ سفارش باز می‌ماند تا راهنمایی مدیر.
- نقد: `cash_collected` همیشه ثبت می‌شود؛ مغایرت با مبلغ سفارش هشدار و گزارش.
- تایمر پیشنهاد سمت سرور مرجع است؛ کلاینت فقط نمایش می‌دهد.
